## 1. pushState 路径路由（2026-08-28 迁移；前身 hash 路由 2026-08-16）

主区三态走**真路径路由**——会话 `/session/<完整会话hash>`、管理视图 `/manage/<kind>`（plugins/projects/models）、项目预览 `/project/<项目label>`（`project` 避开网关 `/preview/*` 静态页路径）；**2026-08-29 用户定案：全部前缀用全称，禁止简写**（同批 `/backend/<label>/` 反代，此前缩写 `/s/`、`/mgr/`、`/pview/`、`/bp/` 仅保留解析兼容、不再生成）；`parseRoute` 先读 `location.pathname`（全称与旧缩写双前缀）、hash 旧链接兜底；网关静态服务带 SPA fallback（`/^\/(?:session\/|s\/|manage\/|mgr(?:\/|$)|project\/|pview\/)/` → 返回 index.html）。`navigate` 参数保持既有 hash 形式（调用点零改动，`#mgr/k`/`#preview/l` 是内部约定 hash 不出现在 URL），内部 `pathFor()` 转真路径：`#/` → `/`、`#/<hash>` → `/session/<全长hash>`、`#mgr/k` → `/manage/k`、`#preview/l` → `/project/l`；`history.pushState` + `popstate` 兜底前进/后退。**URL 用完整会话 hash（2026-08-28 用户定案，不简写）**——上线首版曾只带 32hex 前 8 位按前缀匹配，当日即改全长：URL 直接就是转录文件名（`<uuid>.jsonl` 去扩展名），`findSession` 精确匹配即可，`route()`/`hideGate` 补拉后 resolve（`currentHash`/SSE/WS 全链全长）。

**刷新保留当前界面（2026-08-30 改定案，app v162）**：boot **不再把 `/session/<hash>` 强制重置回首页**（旧「进入/刷新一律默认初始界面」定案作废）——刷新直进时会话列表未就绪由 `renderSession` 占位「加载中」（`needToken()` 门：token 门未过找不到 ≠ 真不存在），WS 验证通过 → `hideGate` 的 `loadSessions().then` 恢复链落地重渲：消息区**无真实消息气泡**（`.msg:not(.msg-system)`）才整页重渲（占位行也是 `.msg`，旧判定对占位恒假会残留），列表就绪仍无此会话才渲染「会话不存在或已删除」。**预览重挂根修（2026-09-04，sw v201）**：hideGate 恢复链原「预览态重挂 iframe」在**每次 WS 重连都执行**——iPad 后台杀 WS 回前台 4s 自动重连必触发，iframe src 恒回站点根，用户被弹回 Pj15 等 backend 站点开始页；现 `openProjectPreview` 幂等（同 label 且 iframe 仍挂载且非 default 兜底误挂 → 跳过重挂保留站内位置，`state.previewMounted` 标记），连带 `initLive` 防重建（每次 hideGate 重复 new EventSource 泄漏旧连接+事件双发，已有 live.es 即跳过）。

**同步路由（2026-08-25，切换会话需双击根治）**：`navigate()` 后**同步调 `route()`**（不依赖 hashchange 异步时序——实测异步 route 内容区不切、要再点一次），`lastNavHash` 去重抑制同值 popstate/hashchange。

**异步边界会话身份校验（2026-08-30 串会话根治，app v170）**：架构对比定案——CLI 单进程单会话（query 循环写内存 AppState、React 同步渲染）不存在跨会话异步边界，串会话结构上不可能；web 是无状态查看器（异步 fetch + SSE 写全局槽 + 全局 DOM），**每个异步边界必须重验 `state.currentHash`**（同构于「渲染前数据必属当前会话」）：①`refreshSession` 在 `await fetchMessages` 后补校验，不通过整体作废（原先只在 await 前查一次 → fetch 回程切会话，上一会话的整份消息/cwd/模型/上下文/队列快照写穿全部全局槽并整页渲进新会话 DOM）；②`renderSession` 切换即清 `live.curUuid` + 置空 `live.queueRemote`，fetch 回来消费 `queued` 硬重置（不清则新会话排队区确定性显示上一会话的 CLI 队列快照）；③`addUser` 忙碌/空闲区分——DOM 有 `done-live`（回合运行中）→ 乐观=排队区成员，无 `done-live`（回合间隙）→ 乐观开启气泡直接进对话流（空闲发送无排队阶段，不短暂显示「排队中」）。

**SPA 路径路由配套（2026-08-28）**：index.html 资源引用与 app.js 动态资源（icon/char/gate）全部改**绝对路径**（`/styles.css?v=138` 等）——`/session/<hash>` 子路径下相对路径会解析到 `/session/…` 404；左上 logo `<a href="#/">` 加 click 拦截走 `navigate('#/')`（pushState 下仅改 hash 不切视图）。

## 2. 会话创建与首条消息链

**新建流程（2026-08-25 定案）= 笔与项目「+」一致，先到初始化界面（空态），发送首条消息才真正建会话**：笔（rail-new/recent-write）清 `state.newProject` 回全局首页；项目文件夹行「+」仅设 `state.newProject=label` + `navigate('#/')`（原空态显示「在 <项目> 新建会话」chip 可点 X 取消，**2026-09-02 chip 移除**——取消/切换目标项目走输入栏项目选择器 seat；**同日定稿 seat 三态**：空态=白底 chip 可点弹层选项目、label 显示项目全称（弃 projIdOf 短编号，max-width 240px）；会话态（`#chat-area.in-session` 门控）=工作文件夹标识保留显示（按当前会话 projectScope/projectLabel 渲染、全局会话显示「全局」）但 `.locked` 锁定只读；管理/预览态挂载点不在 chat-area 自动隐藏），`gwSend` 空态分支带 project 调 `newWebSession(project)`（创建失败恢复 newProject）→ 建会话后才弹 CLI 窗口。

**首条消息立即上屏（2026-08-25 起；2026-08-30 前移为发送瞬间上屏）**：renderSession 首屏 fetch 常抢在 CLI 把首条 user 消息写入 jsonl 前返回空 → 曾闪「该会话暂无 user/assistant 记录」约 1s；现 gwSend 空态分支记首条事务（2026-09-06 起演进为 `firstSendHash` 单变量事务，见下），renderSession fetch 空时乐观上屏（用户气泡+正在处理折叠），真实数据经 SSE 整页替换。**2026-08-30 丝滑建会（用户「初始界面新开会话不丝滑」反馈）**：根因=gwSend 空态分支 `await newWebSession()`（spawn+注册常 >1s）期间界面冻结、返回后才切会话态+闪「加载中…」，且输入栏 stage↔chat 换父后 CSS 过渡首帧跳变。现①乐观渲染前移到发送瞬间（不等 wsession 返回）+ `flipInput(false)` 沉底，失败回滚空态；②新增 `flipInput(toStage)` FLIP 补间：变更前测旧矩形→统一施加类/父容器变更→transform 从旧位滑到新位（终点=恒等无跳变），renderHome/renderSession 换向均走它，隐藏态退回普通切换；③renderSession 在 `webCreating` 且 hash 未定时跳过「加载中…」整洗，保留乐观 DOM。

**三态根治（2026-09-06 首条消息事务化，sw v229）**：用户新会话首条消息实测仍历三态——①发送乐观态 ②顶部「加载中…」+消息被渲染成「排队中」气泡 ③落盘正常态；两轮补丁未净。根因=**状态源发散（6 处）+ 同步 navigate 时序 + DOM 被当状态存储**三者叠加：`navigate()` 同步 route（2026-08-25 改定）→ renderSession 跑在 gwSend await 续体回填 hash **之前**，一切「事后守卫」对第一次洗盘必然失效；洗掉后 fetch 空 + CLI 入队上报 queue-state → 消息以「排队中」形态重现。根治=状态收敛为单变量 `firstSendHash`（''=无事务；非空=该会话首条乐观 DOM 为权威）：hash 回填前移至 `newWebSession` 内 navigate 之前；renderSession 入口切走即作废 + 事务期不洗「加载中…」；fetch/refreshSession 回程非空即收口销毁（双入口对称）；事务期 `renderQueueDock` 直接跳过（注入中消息保持开启气泡形态，不降级排队态）；旧 `pendingFirstSend` 对象、pre/hash 双字段特判、DOM 在场补挂兜底全数删除（不留兜底）。效果：三态归一——发送瞬间直接进入会话视觉并平滑过渡到落盘真实数据，计时不再重开。

**wsession 异步化 + 消息暂存补投（2026-09-06，sw v233，exe 145115；首条消息单状态收口）**：事务化落地后用户实测仍历两态——①wsession 同步等 spawn+注册（1-2s）期间「正在打开本地 CLI 窗口…」toast+乐观气泡的创建态 ②CLI 就绪后的处理态；用户定案「可不可以只有一个状态」。根治 = **`POST /gateway/wsession` 预分配 sid 立即返回**（`sid = resume ?? randomUUID()`，spawn+注册后台进行，不再 await）+ **send 暂存补投**：`spawningPromises` Map（spawn 在途登记，同 sid 并发调用——wsession 与 resumeAndDeliver 竞速——复用同一 promise 防双进程；**2026-09-11 根治：登记须 `p.finally` settle 即清**，此前只 set 不 delete 致该 sid 永久驻留 ⇒ 幂等短路恒命中旧 promise + send 路由恒判「在途」把消息永久暂存，见 §17）+ `pendingDeliveries` Map（send 路由对未就绪会话的消息按序入队；**原「web 会话启动中，请稍后再发送」status = 用户消息无声丢失，随异步化成为常态窗口，根除**）；CLI `/clients` 注册钩子调 `flushPendingDeliveries` 按序补投（cliClients 刚 set 必 OPEN；不 OPEN 保留等下次注册，不丢消息）。失败链不留静默：spawn 失败/注册超时 → handler `.catch` → 清 `pendingDeliveries` + SSE 群发 `{type:'ws-failed', session, error}` → 前端清首条事务 + 移除合成列表条目 + toast 报错 + 当前正看该会话则回首页。配套微调：`renderQueueDock` 事务期不再整段跳过而是**只跳 remote 快照**（flush 投递后 CLI 入队上报、落盘接管前窗口内首条会以「排队中」重现；事务期连发第二条其乐观排队气泡照显，remote 同文项与 local 去重）。效果：发送 → 会话页（乐观气泡+正在处理连续计时）→ CLI 注册（~1-2s 后台）→ 补投 → CLI 处理 → 落盘接管，全程单状态。

**接管帧收口：动画重播+计时回跳根治（2026-09-06，sw v235，exe 154232）**：异步化落地后用户实测仍两态，线索「两个状态的『正在处理』定位不同」。取证=落盘接管帧的视觉跳变双源：①乐观气泡/乐观 proc 折叠**无 data-m**，refreshSession 整页重建的 `stampMsgIn(prevMsgs)` prev 采集只认 `[data-m]` → 同位真实元素被判「新增」重播 `fadeup`（translateY 6px 起步=气泡+「正在处理」跳变重现）；renderSession 切会话路径更是连事务期在位的乐观 DOM 都重播（创建瞬间闪两下）；②`bindLiveFoldTimer` 计时起点=落盘 user ts（异步化后消息经暂存补投，晚于发送瞬间）→ 「正在处理 3s」跨接管回跳成 0s 重数。根治=**接管=同位换皮不是新增**：事务收口帧（`firstSendHash === hash && messages.length > 0`，refreshSession/renderSession 双入口对称）置 `txTakeover` 跳过 `stampMsgIn` + 乐观 `procStart` 经 `live.txProcStart` 移交 `bindLiveFoldTimer`（读取即清）续算——「正在处理 Xs」从发送瞬间连续到落盘接管，气泡/折叠原地无缝换真身。**2026-09-07 判定推广（sw v246）**：CLI 启动会话的 web 首条消息不走 `newWebSession`、无事务庇护 → 同位换皮照旧重播 fadeup + 复制按钮凭空出现。推广 refreshSession 接管帧判定：乐观开启气泡在屏（`[data-t="u"]:not([data-m])`——真实渲染恒带 data-m、引导气泡另带 data-g，无 data-m 的 user 气泡只可能是乐观 DOM）即乐观权威期，与 `firstSendHash` 判定并联；乐观气泡补齐复制按钮（点击为 document 级委托天然可点）与落盘气泡完全同构。

**会话行标识（2026-08-25 定案）= 去「独立」徽标，改项目编号气泡**：`itemHtml(s, showProj)` 删 `webTag`，`renderList`（平铺视图）传 showProj=true 时项目会话（projectScope==='project'）标题后显示短编号气泡（`projIdOf(label)` 取 `^Pj\d+` 前缀如 Pj16，非 Pj 命名回落完整 label，悬停显示完整项目名）；项目文件夹视图/根会话/气泡弹层不显示。

**chat DOM 两区重构：暂态区收编（2026-09-07，sw v248，exe 165544）**：用户实测两症——①「正在处理」折叠收起时发送消息偶发多渲一个「正在处理」（幻影折叠）；②排队消息偶发渲染到上一行（很快自愈）。根因同宗：**乐观/暂态元素与权威数据元素生命周期不同源**——乐观开启气泡直插数据区（整页重建会洗掉）、乐观 proc 折叠挂独立 `proc` 变量+计时器（整页重建后变量悬挂指向失连元素）、`#queue-dock` 独立 msgAppend 挂载（与 delta 增量插入竞争文档序 → 新消息插到 dock 下方）。根治 = **暂态区 `#live-zone`**：数据区与 `.pin-stage` 之间的唯一暂态容器（styles.css `display:contents` 不产生盒，子元素即 `#messages` 直接 flex 参与者；`pin-stage` 恒居末），承载三类元素——回合开启气泡（乐观气泡带复制钮与落盘气泡同构）、回合开启主张折叠（`#claim-fold`，「正在处理 Xs」由 `claimTimerSet` 按最早 `claimTs` 跳字）、置底排队区 `#queue-dock`（原合并/去重/排序逻辑原样迁入）。**单一状态源 `pendingUserMsgs`**（项 `{hash,text,imgs,baseTs,form:'bubble'|'dock',claimTs}`）+ `live.queueRemote`，`renderTransient()` 整体重建：签名不变跳过重建（防 msg-in 动画重播），空区容器整体摘除。每条渲染路径末尾对账，不变量恒成立：**权威 `done-live[data-m]` 在场 → 本区不持回合开启主张**——幻影折叠结构性不可能。权威插入避让：`msgAppend`/`applySegDelta` 插入点取 `#live-zone` 之前（暂态区恒贴底）。首条消息事务收口同步迁移：接管帧 rebase `hash:''` 项归入本会话 + `claimStartTs()` 经 `live.txProcStart` 移交 `bindLiveFoldTimer` 续算（计时跨接管不回跳）；撤回链（restored）同步丢弃匹配 pending 项。**死代码清剿（网关从不投递 WS `out`/`result`/`system`/`err`，2026-09-07 定案）**：`handleLine`/`streamText`/`streamThinking`/`procThink`/`procTool`/`procResult`/`procAsk`/`addToolResult`/`addThinking`/`toolChip`/`startReply`/`addAssistant`/`procOpen`/`procClose`/proc 变量族/`liveChanges`/`liveAskInput` 全链退役（约 -300 行），`procLabel`/`toolLine`/`toolMeta`/`toolToChar` 保留（数据侧在用）。**队首主张收编（2026-09-08，sw v258，exe 124915）**：刷新两段式根治——刷新撞上「消息已入队、未落盘」窗口时，首次 fetch 回程 jsonl 无回合开启消息而 `queued` 快照已有 → dock 先出「排队中」、气泡+折叠体等落盘后才出现。`queueClaimAdopt(items)`（首载回程/防抖回程/queue-state SSE 三入口统一调用）把队列**队首项**收编进 `pendingUserMsgs`（form='bubble'；同文本已收编/本地已发 dock 项幂等跳过或原地升级；首条消息事务期豁免），形态由 `renderTransient` 现成 authLive 判定自动定——权威 `done-live` 在场（回合运行中）→ 降级 dock 成员=真排队；不在场（回合间隙）→ 气泡+主张折叠=即将出队开新回合的瞬态；非队首项恒走 remote 真排队。收编项落盘后走 absorbPending 文本接管/接管帧同位换皮/claimStartTs 计时移交。

## 3. 共同后端架构（2026-08-30 定案 + 实施）

CLI = 前端（React/Ink）+ 后端（会话引擎：query 循环 + commandQueue + AppState）同进程；**会话引擎为 CLI 与 web 的共同后端，二者地位等权**；网关退化为**纯路由**（会话注册表 / 按 sessionId 转发 / SSE 广播，不做任何渲染语义加工）；**jsonl 降级为冷数据**，只用于历史回放（由同一份 `filterConversationForDisplay` 输出）。

**web/CLI 等权处理原则**：**等权的本体 = 二者共用同一个后端（会话引擎），CLI 和 web 只是同一后端的两种前端**——无主从、无镜像关系；唯一真源是后端语义，两个前端都只是「呈现 + 输入」的视图层。由此推出三条：
- **能力等权**：后端暴露的每个会话能力，两种前端都应有入口——审批/提问双操作竞速、发送/引导注入（同一 enqueue 写入口）、模型切换双向同步、队列预览（queue-state 快照链）、重命名实时互同步、web 独立会话=本地可见 REPL 窗口与普通 CLI 同路径。**新能力先落在后端（引擎/导出），两种前端各自接线**；不允许只给一个前端做。
- **正确性等权（结构性代价，v170 串会话根治定案）**：两种前端向前端无关的后端语义对齐，但各自的运行结构不同——CLI 单进程单会话，「渲染的数据必属本会话、状态随进程生灭」这些保证是**结构免费**的；web 是无状态查看器（多会话随时切换 + 异步取数），同保证必须**显式补齐**：每个异步边界（fetch 回程/SSE 事件/防抖定时器）重验 `state.currentHash`、切会话即清全局槽、乐观语义按后端实际行为分流（回合中=排队预览、回合间隙=立即开新回合）。

## 13. 排队消息催办：点击排队气泡打断当前思考（2026-09-10 用户定案，sw v294，exe 202425）
